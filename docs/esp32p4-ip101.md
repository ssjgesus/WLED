# ESP32-P4 IP101 port

Based on upstream WLED commit 674f2a8927117923c3343f3271886c9cff1a5026.
The pin configuration follows the IP101 initialization in
https://github.com/troyhacks/WLED/blob/P4_experimental/wled00/wled.cpp
and Espressif's Arduino ETH_TLK110 example (IP101 is the driver's underlying PHY).

Copy tools/esp32p4-ip101.ini to platformio_override.ini, then run npm ci,
npm run build and pio run -e esp32p4_ip101. This targets the JC-ESP32P4-M3-DEV
with 16MB flash and the upstream 16MB partition layout. The example enables
Ethernet-only operation. Remove WLED_USE_ETHERNET_ONLY to retain Wi-Fi.

The existing Ethernet profile ID 7 is labelled ESP32-P4 IP101 on P4. Other
classic ESP32 Ethernet profiles are rejected. PHY address is 1, MDC 31,
MDIO 52, reset 51, and external RMII clock input 50. Arduino's P4 RMII
pin definitions supply TX_EN 49, TXD0 34, TXD1 35, RXD0 29, RXD1 30,
and CRS_DV 28. GPIO35 must not be configured as a WLED button.

Firmware.bin is the application OTA image. Do not OTA this over a firmware
with incompatible app partition sizes or filesystem layout. In particular,
Troy's 8MB partition configuration is not the upstream 16MB layout. Back up
presets/configuration and use a full serial flash for that migration.

This port adds Ethernet, not PARLIO. At this upstream revision PARLIO is an
unsupported capability placeholder; the seven-output Troy configuration
cannot be transferred and assumed to work. Keep the working firmware for
that display until LED driver support is separately implemented and tested.

Hardware validation still required: cold boot, DHCP, static IP, cable removal
and reconnection, OTA, and sustained DDP reception. Ethernet-only mode has no
Wi-Fi recovery AP; serial recovery is needed if Ethernet is misconfigured.
